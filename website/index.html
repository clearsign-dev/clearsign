    The problem

    Nobody reads the bytes

    Your hardware wallet shows you a hash. Safe{Wallet} shows you a decoded summary produced by a service. Neither of those is the transaction — they are descriptions of it, and a description can be wrong.

    On 21 February 2025 that gap cost Bybit about $1.5 billion. Every signer looked at what appeared to be an ordinary token transfer. What they approved was a DELEGATECALL that ran someone else's code with the Safe's own storage and balance.

    ClearSign closes the gap by refusing to trust anything except the bytes you are signing.

    Coverage

    What it reads

    • Safe multisig transactions

      Decodes execTransaction and recomputes the EIP-712 safeTxHash from the bytes, so you can hold it against the hash on your hardware wallet. It works out the Safe domain from the record or refuses — and a v1.1.x domain, which omits the chain ID and is therefore replayable on another chain, is named as CRITICAL rather than quietly signed.

    • Batched calls

      MultiSend batches are unpacked and every inner call is shown, against 11 pinned deployments and 1,404 verified address-chain pairs. A delegatecall inside a batch, an unpinned batching contract, a truncated batch or an over-long one all stay CRITICAL and undecoded.

    • Transfers and approvals

      Token contract, recipient and amount in raw integer units, with no helpful rounding. An approval large enough to be effectively unlimited is called that, not rendered as a number nobody counts the digits of.

    • Air-gapped QR requests

      Reads signing requests the way a real air-gapped device does — Uniform Resources, Bytewords and multipart fountain codes, checked against the vectors published in BCR-2020-012 and BCR-2024-001, plus EIP-4527. The same format MetaMask and Keystone already speak. What the wallet claims about the chain, the signer and the wallet fingerprint is compared with the signed bytes, and disagreements refuse.

    • What an AI agent wants to do

      The authority engine takes a plan an agent proposes, traces where data would flow, and requires a person to approve each finding by name. The planner does not get to classify its own data: a step that would carry a secret off the device is CRITICAL even when the proposal labels it public.

    • And what it refuses

      EIP-712 typed data is not covered yet, and ClearSign says so instead of guessing. Anything it cannot fully account for is reported BLIND, and BLIND or CRITICAL always ends in DO NOT SIGN. A reviewer that answers every question is not a reviewer.

    Three ways to run it

    How it ships

    The same decoder, in three shapes: one you install, one you script, and one that is the whole computer.

    Desktop app

    A window, not a terminal. Paste a transaction, drop a file, or fetch a queued one by its hash.

    • macOS, Windows and Linux, built from the same Rust core
    • Twelve networks, chosen explicitly rather than guessed
    • Every review kept locally; nothing is sent anywhere
    • A record you can copy and hand to the other signers

    Builds on all three. Not yet code-signed.

    Command line

    For the people who already live here, and for anything that needs an exit code.

    • clearsign safe-json tx.json --chain-id 1
    • clearsign qr-review scanned-codes.txt
    • Exit 0 nothing alarming, 2 undecodable, 3 CRITICAL
    • Reads Safe's own JSON, and ignores its dataDecoded

    Working. Safe on any computer.

    Signer image

    A Linux image containing exactly one program, on a kernel with no network stack compiled into it.

    • Five build gates refuse a kernel with networking, a dynamically linked signer, or anything resembling a shell
    • Under seL4, the untrusted Linux compartment has no serial device and no shell
    • Two builds of the same content produce an identical kernel and initramfs
    • Boots in QEMU with no network device attached

    Runs under emulation. No hardware yet.

    Get it

    Run it before you approve

    • Install the app

      Installers for macOS, Windows and Linux are published with their hashes on each release.

    • Or build it yourself

      cargo test --workspace --release — then run the reviewer against a transaction you already trust, and see whether it agrees with you.

    Early development. Unaudited beyond one review. Not for real funds. Reviewing a transaction is safe on any computer. The signing and seed commands are locked behind an environment variable, because a recovery phrase typed into an everyday machine must be treated as exposed.
